# Packaging Voice Companion

Voice Companion ships as a Developer ID–signed, notarized DMG holding
`Voice Companion.app`: a menu bar app (`LSUIElement`) built from the
`VoiceCompanion` product of this package.

| File | What it is |
| --- | --- |
| `Info.plist` | Bundle metadata. The two version keys hold `0.0.0`; the build script replaces them. |
| `VoiceCompanion.entitlements` | Hardened-runtime entitlements for a non-sandboxed app: microphone input and Apple Events. Nothing else. |
| `VERSION` | The version the build uses when it is not given one. |
| `AppIcon.icns` | Generated by `scripts/companion-icon.swift`; committed so builds need no drawing step. |

## Build and sign

```sh
scripts/companion-build-dmg            # version from VERSION
scripts/companion-build-dmg 0.2.0      # or name it
IDENTITY="Developer ID Application: …" scripts/companion-build-dmg   # pick a signing identity
```

It uses the swiftly toolchain when `~/.swiftly/env.sh` exists, `swift` from `PATH`
otherwise, and Xcode's `codesign`, `hdiutil`, `lipo`, `otool` and `vtool`.

Output: `dist/Voice Companion.app` and `dist/VoiceCompanion-<version>.dmg`, plus the
DMG's SHA-256. Each run deletes the app, that version's DMG and its staging folder
first, so it can be repeated.

What it checks, failing the build on any miss:

- the version is one to three dot-separated integers;
- the release build is universal (arm64 + x86_64), judged by `lipo -archs` rather
  than the exit code; if that build fails it says so loudly and falls back to arm64
  only, and the result will not run on Intel Macs;
- `otool -L`: the binary links nothing outside `/usr/lib` and `/System`, because
  nothing else is embedded in the bundle;
- `vtool`: the binary's minimum macOS is not newer than `LSMinimumSystemVersion`;
- the app is signed with the hardened runtime, the entitlements and a secure
  timestamp, then `codesign --verify --deep --strict` passes;
- the DMG (UDZO, volume "Voice Companion", the app plus an `Applications` link) is
  signed with a timestamp and verifies.

It also warns if SwiftPM produced resource bundles, which it does not package yet.

The DMG is signed but not notarized. Until it is, Gatekeeper answers
`rejected (source=Unnotarized Developer ID)`; that is expected.

## Notarize

```sh
scripts/companion-notarize                              # newest dist/VoiceCompanion-*.dmg
scripts/companion-notarize dist/VoiceCompanion-0.1.0.dmg
```

Credentials, first match wins:

- `NOTARY_PROFILE`: a keychain profile made with `xcrun notarytool store-credentials`;
- `NOTARYTOOL_KEY` (an App Store Connect `.p8`), `NOTARYTOOL_KEY_ID` (read from an
  `AuthKey_<ID>.p8` file name when unset) and `NOTARYTOOL_ISSUER` (required for team keys);
- otherwise the keychain profile `remotty-notary`.

What it does:

1. Verifies the DMG's signature, then uploads it with
   `notarytool submit --wait --timeout 30m`.
2. On a 403 about a missing agreement, says what the account holder must accept and
   stops. On `Invalid` or `Rejected` it prints Apple's log and exits non-zero. On a
   timeout it prints the submission id to resume with `notarytool wait`.
3. On `Accepted`: staples the ticket to the DMG and runs `stapler validate`.
4. Checks the DMG as a user's Mac will: `spctl -a -t open --context
   context:primary-signature`, then mounts it read-only and requires
   `spctl -a -t exec` on the app to report `source=Notarized Developer ID`. The image
   is always detached.

Run it again on a DMG that is already stapled and it skips the upload and only runs
the checks.

The ticket is stapled to the DMG, not to the app inside it, because the compressed
image can't change once it is signed. That ticket covers the app too: macOS reads it
when the user opens the DMG, and can look it up online for the copied app.

## Icon

```sh
swift scripts/companion-icon.swift /tmp/AppIcon.iconset
iconutil -c icns /tmp/AppIcon.iconset -o Packaging/VoiceCompanion/AppIcon.icns
```

The script draws every size from 16 to 1024 pixels at its exact pixel size. Commit
the regenerated `AppIcon.icns`.
